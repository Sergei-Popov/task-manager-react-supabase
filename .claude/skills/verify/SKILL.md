# /verify — проверка по протоколу docs/TESTING.md

Аргумент (необязательно) — что именно изменилось; по нему выбирается объём. Без
аргумента прогоняется всё.

## 1. Подготовка

```bash
npm run lint && npm run build
export DOCKER_HOST=unix://$HOME/.colima/default/docker.sock
docker compose up -d db
curl -sf http://localhost:5173/api/health || echo "поднять: npm run dev:all"
```

Если dev-серверы не запущены, запустить их в фоне (`nohup npm run dev:api …`,
`nohup npm run dev …`) и дождаться `{"ok":true}` через прокси Vite.

## 2. Функциональный сценарий

Взять пункты из раздела «Обязательный функциональный сценарий» `docs/TESTING.md`,
которые касаются изменения (всё, если изменение широкое или аргумента нет).
Использовать Playwright MCP (`browser_navigate`, `browser_fill_form`,
`browser_click`, `browser_snapshot`) и curl к `http://127.0.0.1:3001/api`.
Каждое действие, меняющее данные, сверять с базой:
`set -a; source .env; set +a; psql "$DATABASE_URL" -Atc "…"`.
Тестовый аккаунт: `sergei@example.com` / `Secret1!`, либо новая регистрация.

## 3. Визуальный прогон

Для 1280×800 и 390×844 снять скриншоты экранов из таблицы `docs/TESTING.md`,
затронутых изменением (все, если изменение широкое). После каждого скриншота:
переместить файл в scratchpad, открыть через `Read`, посмотреть и записать
замечания. Проверить `scrollWidth === clientWidth` и
`browser_console_messages` с `level: error` — должно быть пусто.

Смотреть на: наложения, слишком тесные элементы (зазор между кликабельными меньше
8 px), обрезанный текст, неверная тема, пустые состояния, тосты поверх важных
элементов.

## 4. Исправить и повторить

Каждое найденное замечание исправить сразу, повторить затронутый пункт. Закончить
только при чистом прогоне. Удалить `.playwright-mcp/` и скриншоты из репозитория,
закрыть вкладку браузера.

## 5. Отчёт

Список: что проверено (экран, ширина, сценарий), чем (браузер/curl/psql), что
нашлось и как исправлено. Если что-то не удалось проверить — сказать прямо.
