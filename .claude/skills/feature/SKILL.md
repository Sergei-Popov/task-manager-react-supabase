# /feature — новая фича от идеи до проверенного коммита

Аргумент команды — описание фичи словами пользователя. Идти по шагам строго по
порядку, не пропуская. Между шагами 1 и 3 обязательно ждать подтверждения.

## Шаг 0. Контекст

Прочитать `CLAUDE.md`, `CONTEXT.md`, `docs/ARCHITECTURE.md` и те части кода, которые
затронет фича. Проверить `docs/adr/` на конфликты. Факты о коде выяснять самому,
не спрашивать у пользователя.

## Шаг 1. Гриллинг

Вызвать навык `grilling` через Skill tool и провести интервью раундами. Обязательно
закрыть эти ветки, если они применимы:

- какую проблему пользователя решает фича и как он поймёт, что она работает;
- где именно в интерфейсе (список / канбан / календарь / модалки / сайдбар / лендинг),
  на десктопе и мобильном;
- данные: новые поля, миграция, значения по умолчанию, что с существующими записями;
- API: новые эндпоинты или изменение существующих, ошибки и их тексты;
- поведение в крайних случаях: пусто, много, просрочено, чужой пользователь, оффлайн;
- что явно НЕ входит в задачу.

Если фича трогает термины, параллельно вызвать `domain-modeling` и обновить
`CONTEXT.md`. Интервью закончено только когда пользователь подтвердил понимание.

## Шаг 2. Спецификация

Записать `docs/specs/<YYYY-MM-DD>-<slug>.md` с разделами: Проблема, Решение,
Пользовательские истории (нумерованный список «Как <кто>, я хочу <что>, чтобы <зачем>»),
Решения по реализации (модули, схема, API, без путей к файлам), План проверки
(какие пункты `docs/TESTING.md` и какие новые сценарии), Вне области. Показать
пользователю краткое резюме и спросить «начинаю?». Без ответа «да» не переходить дальше.

## Шаг 3. Реализация

Следовать `docs/AI-RULES.md` раздел 2. Порядок: миграция → сервер (роут +
валидация + `docs/API.md`) → `src/utils/api.js` → стейт и обработчики в
`DashboardPage.jsx` → компоненты shadcn. `npm run lint` после каждого блока.

## Шаг 4. Проверка

Вызвать навык `verify` (Skill tool, имя `verify`) с описанием того, что изменилось.
Все найденные ошибки исправить и снова прогнать `verify`. Не переходить к шагу 5,
пока проверка не чистая.

## Шаг 5. Документация и коммит

Обновить `docs/ARCHITECTURE.md`, `docs/API.md`, `CLAUDE.md` (если появилось что-то
неочевидное), `CONTEXT.md`. Убрать временные файлы. Сделать коммит (сообщение на
английском, тело со списком изменений). Пуш только по просьбе.

## Шаг 6. Отчёт

Коротко: что сделано, что и как проверено (экраны, ширины, сценарии, проверки в
базе), что осталось за рамками. Без обещаний того, что не сделано.
