# Проверка и визуальное тестирование

Автотестов в проекте нет. Каждое изменение проверяется вручную агентом по этому
протоколу: через API (curl) и через браузер (Playwright MCP или Chrome MCP) со
скриншотами, которые агент обязан открыть и посмотреть.

## Перед проверкой

1. `npm run lint` и `npm run build` чистые.
2. Запущены: Postgres (`docker compose up -d db`), API (`npm run dev:api`, порт 3001),
   Vite (`npm run dev`, порт 5173). Проверка: `curl -s localhost:5173/api/health` → `{"ok":true}`.
3. Для production-проверки: `docker compose up -d --build`, адрес http://localhost:8080.

## Обязательный прогон после любого изменения интерфейса

Ширины: **1280×800** (десктоп) и **390×844** (мобильный). Для каждой:

| Экран | Что проверить |
| --- | --- |
| Лендинг `/` | шапка, hero, карточки, превью, футер; нет наложений и горизонтального скролла |
| `/login`, `/registration` | поля, ошибки валидации, ссылки между страницами |
| Дашборд, список | сайдбар, быстрое добавление, статистика, панель фильтров, группы, карточки |
| Дашборд, канбан | три колонки, карточки, «+» в заголовке, перетаскивание |
| Дашборд, календарь | сетка (десктоп) или список дней (мобильный), «+» на дне |
| Модалки | новая задача, просмотр, редактирование, категория, теги, подтверждение удаления |
| Тема | светлая и тёмная через переключатель в шапке |

Критерии: элементы не накладываются, между соседними кликабельными элементами
есть зазор, текст не обрезается без `truncate`, `document.documentElement.scrollWidth
=== clientWidth`, в консоли браузера нет ошибок (`browser_console_messages level=error`).

## Обязательный функциональный сценарий

1. Регистрация нового пользователя → попадание на дашборд с его email в сайдбаре.
2. Создание категории и тега.
3. Создание задачи через полную форму: срок через пикер, категория, приоритет,
   повторение, подзадача, тег, цвет. Проверить в БД:
   `psql "$DATABASE_URL" -c "select * from tasks order by created_at desc limit 1"`.
4. Быстрое добавление: текст + Enter → задача в группе «Сегодня»/«Завтра».
5. Смена статуса тремя способами: Select на карточке, кружок «выполнено», перенос в
   канбане (клавиатура: фокус на ручке → Space → стрелка → Space).
6. Просмотр задачи, отметка подзадачи чекбоксом, редактирование и сохранение.
7. Удаление задачи, категории, тега — через диалог подтверждения; тосты появляются.
8. Выход → редирект с `/dashboard` на `/login` → вход обратно.

Если что-то из этого затронуто изменением, сценарий прогоняется целиком; если
изменение локальное, минимум пункты, которые его касаются, плюс визуальный прогон.

## Как снимать и смотреть скриншоты

- Playwright MCP: `browser_resize` → `browser_navigate` → действия →
  `browser_take_screenshot` с осмысленным именем → переместить файл в scratchpad →
  открыть через `Read` и **реально посмотреть**. Скриншот, который не открыли, не
  считается проверкой.
- Не оставлять `.playwright-mcp/` и `*.png` в репозитории (`rm -rf .playwright-mcp`).
- Нельзя вызывать `window.confirm`/`alert` в тестах: их нет в приложении, а в
  браузере они блокируют сессию.

## Проверка API без браузера

Смотри примеры в `docs/API.md`. Обязательно проверить, что второй пользователь не
видит и не может изменить данные первого (ожидаются `[]` и `404`).

## Что делать при найденной ошибке

Исправить, снова прогнать затронутые пункты, только потом отчитываться. В отчёте
перечислить, что именно проверено и каким способом.
